# 坦克送达与射击改造实施方案

日期：2026-10-18。状态：已按最终契约实现，51项JVM及正常屏/小屏原生回归通过，独立审核通过；新版APK已安装到已连接手机并成功启动。入库验收记录见 [玩法验收](gameplay-validation.md)；逐轮日志与审核保留在本地 `out/tank-delivery/`。真机操作手感由用户试玩确认。

## 深度交互：目标、边界与最简方案

目标是将原载具掉落机会替换为可观察的 NPC 送坦克过程，并使骑乘操作变为移动与有限弹药射击。沿用单 Activity、Canvas、GameWorld 和现有锁，不增加游戏引擎、事件总线、通用实体框架或波次管理器。

改造前代码把 CAR/TANK 放在 FallingItem 枚举内，接触即可上车；Player 保留 vehicleKind，GameView 从掉落位图表取载具，ControlsBar 直接调用跳跃，HUD 只携带骑乘/撞击/秒数。这些路径必须一起替换，不能仅隐藏汽车、换帮助文案或为旧测试保留落坦克上车后门。

最小状态为一个可空送车实体、一个独立返回 NPC 列表、一个炮弹列表，外加 Player 的弹药和最后开火方向。猛兽来向从现有 beasts 推导，避免缓存与实际存活列表失配。返回 NPC 与坦克是否仍在等候完全解耦。

规划阶段只读取代码及已有记录、写两份计划；实施与验收结果另见文首状态及验收记录。现有未提交 score-stages 是实施基线，不覆盖、不回退、不据旧提交重建文件。主线程已通知 README/AGENTS/store 文档完成更新；这些文件由主线程管理，实施线程不得重写。文档同步状态与产品实现状态分别记录。

| 骑乘 | 15 秒或累计 3 次撞击先到报废；仍接食物、可左右移动、不能跳跃或主动下车。危险物撞毁仍得 3 分 |
| 换车补给 | 骑乘者地面接触停稳新坦克：从接触时刷新 15 秒、补满 3 发，不清累计撞击；新坦克消失，返回 NPC 继续跑。已报废后再上车才将撞击归零 |
| 射击 | 原跳跃键显示射击和剩余弹数；一次按下发一发，长按不连发，总计 3 发。弹尽只禁动作区，移动继续；报废立即恢复跳跃 |
| 炮弹 | 水平直飞、方向生成后不变、不跟踪、不穿透，只打猛兽；命中一只后消失，炮击不耗撞击次数。已发炮弹在坦克报废后继续至命中或离场 |
| 兽分值 | 碰撞撞毁或炮击杀狼均 5 分，虎/狮均 10 分；同一只兽仅结算一次 |
| 同向批次 | beasts 非空时新兽沿现有兽相同方向进入；全灭或全部离场后，下次实际生成重新随机一侧。批次不改变数量、解锁、频率或跳跃规则 |
| 开火方向 | 有兽：方向=-beasts.first().direction，朝兽的来向，不依据玩家移动方向；无兽：保持本局最后实际开火方向；首次上车设置默认朝向：左侧送来向右、右侧送来向左；移动不改变默认朝向 |

| 不变项 | 51/101/201/301 严格超过门槛、600 分兽间隔封顶、掉落时间曲线、背景、生命/无敌/额外生命、排行榜、BGM 与既有音效资源保持 |

## 状态、几何与生命周期

### 最小数据结构

- `TankDelivery`：x、来侧/驶入方向、目标位置、尺寸、驶入/等候状态、停稳时间。只需两态，不把 NPC 返回塞进同一状态机。
- `ReturningNpc`：x、返回方向、尺寸及移动速度；保存在 world 的小列表，越过原侧边缘后删除。可与 TankDelivery 放同一文件，避免无收益的文件拆分。
- `Bullet`：当前/上一位置、固定 y、方向、尺寸、速度；只在成功开火时创建。无需所有者、伤害层级、弹药系统或追踪目标。
- `Player`：保留 riding、vehicleHits、vehicleExpiresAtMs；新增 ammoRemaining、可空 lastFireDirection、supplyVersion，删除 vehicleKind。`mount(nowMs, defaultDirection)` 接收送车方向，不再接收掉落种类。supplyVersion 仅标识实际接车次数，让满弹补给也能清动作触点。状态函数可以直接单测，但生产唯一上车调用源是 world 中停稳接触分支。
- world 持有上述实体，GameSession 已持有 world；View/Activity 只消费状态与绘制，不复制物理状态或保存另一份弹药。

全部新增可调参数放 GameConfig：15_000ms、3_000ms、3 发、送车速度、NPC 返回速度、坦克/NPC/炮弹尺寸、炮弹速度及炮口偏移、停车位置比例、NPC 区分颜色/帽子尺寸、狼 5 分与虎狮 10 分。复用既有撞击上限和 75% 判定比例。不将 4% 拆成新的额外定时器或重新调概率。

未由用户指定的速度和视觉尺寸是首版调参项，实施选取能看清驶入/下车/射击的配置值并记录，设备验收再确认；不是新玩法决策阻塞项。首次默认朝向由送车侧确定，不在开火时根据玩家当前位置重新计算。

### 送达、等候及地面接触

沿用世界游戏时间，不使用墙钟 Handler 定时。驶入时将位移夹紧到目标；到达该帧设置停稳时间并只生成一次返回 NPC，从此开始完整 3 秒等待，不扣除驶入耗时或整个到达帧的 dt。同帧允许已在地面接触位置的玩家立即上车。

等候有效区间为 `[stoppedAt, stoppedAt + waitMs)`；到期时先移除，不能在恰好 3 秒或之后补上车。停稳与到期的边界测试采用可控小步时间。

地面资格使用 `!player.isAirborne(now)`，不能只看纵向图像相交，因为起跳第一帧视觉偏移仍可能为零。通过地面角色/骑乘底座与停稳坦克的有效水平接触区判断，避免直接使用被骑乘偏移抬高的人物受伤框导致补给接触失效。有效接触尺寸沿用显示尺寸的 75%；普通受伤判定不随此次改造扩大。边相切维持既有 Aabb 的不相交规则。

首次上车清跳跃状态、撞击归零、弹药补满；续骑保留撞击，刷新时长和弹药。世界先处理已有坦克到期再检查新车接触，因此恰好到期时接触属于新上车；规则写入测试，不依赖遍历顺序。

返回 NPC 从停稳位置独立运动；无人坦克消失或被取走不会清返回列表。已有返回 NPC 时允许后续送车及多个返回 NPC 共存，数量由实际送达频率与出屏清理自然限制，不人为丢 NPC。

### 批次、瞄准与动作入口

生成猛兽时取 `beasts.firstOrNull()?.direction`；空场才随机来侧，种类仍随机。每次生成查询当前实际列表，不增加波次方向缓存。沿用现有生成先于本帧实体更新的顺序：生成瞬间还有兽就属于原批；本帧稍后全离场/被杀后，下次生成随机，不在同帧补发下一批。

将 ControlsBar → GameView → GameWorld 的跳跃调用改为统一动作调用（如 `performPlayerAction`）。GameView 在既有 `synchronized(world)` 内拒绝 released/暂停/菜单/死亡；world 再核验尺寸、死亡、骑乘有效期、riding 和弹药，再决定跳跃或射击。Player.jump 自身也拒绝骑乘，不能通过旧调用入口使坦克起跳。

成功发射才扣弹、创建炮弹、更新 lastFireDirection，并立即发布含弹药和接车版本的 HUD；弹尽不创建、不扣成负数、不改最后方向、不误跳。未骑乘时只允许正常跳跃；过期但 HUD 尚显示射击时以世界真实状态执行。移动方向从不覆写 lastFireDirection，补给不重置最后方向，新一局才重置。

## 炮弹扫掠与同帧结算

当前碰撞按更新后 AABB 检查，高速炮弹若只查终点会跳过猛兽。新增一个小型纯 Kotlin 扫掠函数，放 Bullet 或 Aabb 附近，不依赖 Android RectF，也不做通用物理引擎。

1. 保存本帧炮弹与兽的起点判定框，更新兽/炮弹至终点。对每对候选，用炮弹位移减兽位移形成相对位移，将兽起点 AABB 向外扩展炮弹半宽/半高，再做线段与扩展框的 slab 相交求进入时间 `t∈[0,1]`。零轴速度单独处理；起点已重叠按 t=0；只有相切不算命中。
2. 采用兽的起止 y 位移参与相对扫掠，不能用整段包围大矩形代替，否则炮弹会误杀跳到上方的兽。跳跃是正弦曲线；对跨越起跳、顶点或落地的运动段按阶段边界分段，以分段起止框求相交，必要的最大物理子步集中配置，验收覆盖最高生产 dt 50ms 与跨跳跃阶段的长步。不得为了测试大 dt 改坏现有生成计时或补刷多只兽。
3. 所有候选按进入时间从早到晚处理，时间相同时用稳定列表顺序作平局规则。仅炮弹与兽都仍存活时结算：删除/标记该兽与该弹，计分一次。某弹较早候选已被其他弹杀掉时可继续检查它路径上的下一只存活兽；不能让已删除目标再次得分，也不能让已命中炮弹穿透。
4. 再处理剩余兽与玩家的碰撞。炮击和撞击同帧争抢同兽时明确采用炮击优先，撞击遍历只见存活兽；此时不消耗耐久。不要求额外计算所有玩家碰撞的连续时间，保留原玩家碰撞方式。
5. 炮弹越界清理放在路径命中计算之后，避免本帧先穿兽后出屏却被提前删除。兽本帧离场也保留到扫掠结束再删除，避免高速相向交叉漏判。

世界更新仍以帧开始 score 快照决定生成/跳跃，碰撞新增分数下一帧解锁。先更新骑乘到期与送车/接触，再保留现有掉落物结算；若掉落物已致死，当帧直接停止后续炮击/兽计分。然后进行兽运动、炮弹命中与剩余兽接触，完成离场清理和 HUD。死亡后其余处理立即终止，addScore 的死亡拒绝保留，面板/数据库/显示分数一致。

狼/虎狮的奖励用一个局部函数或 Beast 的只读分值属性按 kind 映射配置；撞毁与炮击调用同一映射。炮击不调用 registerCrush，撞危险物及撞兽才消耗次数。第三次撞击仍完成本次击杀和分数，然后下车；同帧后续碰撞使用最新骑乘/生命状态。

已发射炮弹不绑定 riding，不在 tickVehicle/registerCrush 中清理；报废后仍可正常击杀得分，死亡后则冻结且不得加分。reset/回菜单明确清空全部新增实体与方向状态。

## UI、绘制、语言与资源清理

扩展 GameWorld.Listener、GameView.HudListener 及测试 Probe 的骑乘通知，增加 ammoRemaining 和 supplyVersion；publishVehicleHud 比较弹药和接车版本变化，成功动作结束立即通知，补给/上车/报废在该帧结束前通知，不等待下一秒倒计时。保留 refreshHud 的强制发布，以及 GameView.postHud 的 eventVersion、released、listener 身份过滤，避免旧局/旧 Activity 回调污染新画面。

ControlsBar 将 jumpArea 语义改为动作区，保存可更新的文本与 contentDescription：未骑乘“跳跃”，骑乘“射击 · 剩余 N 发”。门控分两层：整体游戏允许时移动可用；动作区还需未骑乘或弹药>0。setEnabled/refreshControls/焦点恢复不能覆盖弹尽禁用，弹尽时不可禁整个控制条。

沿用 DOWN 单次执行、MOVE 不触发、UP/CANCEL 清理、performClick 无障碍单次动作。模式切换/补给/报废/换边/暂停清理动作指针与按压态；倒计时或撞击数单独变化不清理动作指针，不合成新 DOWN、不使仍按住的手指自动开火；仅动作状态变化不要清移动指针，双指移动连续。world 内校验保证异步旧 HUD 下快速多按也最多消耗 3 发、不能坦克跳跃。

GameView 独立加载 tankBmp，不再依赖 ItemKind。送车、等候与骑乘共享坦克素材，使用明确目标 Rect 缩放与左右镜像，不能沿用 drawSprite 在有位图时忽略 size 的行为造成判定/显示不一致。炮口高度与地面兽可命中区域相符；枪口及坦克显示方向和实际发弹方向一致。NPC 复用 playerBmp 缩小、帽子/改色绘制，Canvas save/restore 及 Paint 颜色过滤及时复原，不能污染主角绘制。缺图仍实心占位，不崩溃，不加掉落外圈。

帮助图标从 car 改 tank；中英帮助、教学、按钮、无障碍说明同步覆盖送达、地面接触、3 秒、15 秒/3 撞、3 发/弹尽、狼分值和同向来兽。设置换边偏好继续使用已有 key，不做存储迁移；显示文案应说明跳跃/射击共用动作键。

GameSession.world 保留全部新增状态，包括驶入/停稳时间、返回 NPC、炮弹、弹药、撞击、最后方向及原阶段计时。语言重建时 release 只解绑旧 View、停止旧循环/回调、释放其位图引用，不 reset world；新 View 安装 listener 后强制刷新 HUD/动作区，以新语言渲染。不得让 onSize/prepareSprites 重建送车或刷新弹药；同尺寸重建位置与倒计时保持。

重开/回菜单走现有 reset，清新增状态并发布跳跃 UI；暂停/教学/设置/后台停止更新与输入，返回时恢复原剩余时间，不补算后台墙钟。死亡冻结世界和分数，切换菜单后才清空。离场炮弹/NPC按帧删除，避免列表无界增长。释放 View 的位图引用不销毁 GameSession 实体；不把 Context/Bitmap/Handler 放进实体。

音频继续由 MainActivity.applyAudioState 管理；上车复用 MOUNT、击杀复用 CRUSH、真实起跳才播 JUMP，拒绝动作不误播跳跃。未要求新增开炮音效，本次不扩充 SoundEvent 或音频资源。
